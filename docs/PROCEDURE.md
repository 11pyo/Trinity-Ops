# 업무 절차 (Operating Procedure)

Trinity-Ops 는 새 기능을 만든 것이 아니라 **이미 있던 부품을 한 절차로 묶은 것**입니다. 이 문서가 그 절차의 정본입니다.

## 1. 흐름

| 단계 | 누가 | 어디서 | 남는 것 |
|---|---|---|---|
| ① 접수 | 요청자(현업) | 접수 창구 `chat-ui` — 사번 로그인, 문의 1건 = 대화방 1개 | `inquiry-log.js` 에 새 문의(상태 「접수」) |
| ② AI 1차 응답 | 트리니티봇(읽기 전용) → **쓰기 게이트** | `vacation/watcher.py` → `apply_answer.py` | 「[트리니티봇 · AI 1차 안내 · …]」 표기가 붙은 답, 상태 「대기」 |
| ③ 사람 검토 · 판정 | 담당자 | 문의 데스크 `desk` (127.0.0.1) | `botgrade`(맞음 · 보완 · 틀림) + 이유 코드 + 메모, 필요하면 사람 답을 이어 붙임 |
| ④ 검증 장부 | 자동 집계 → 사람 결정 | `vacation/ledger.py` · 봇 지표 화면 | 유형별 정확도 · 95% 하한 · 권한 단계표 — **기준을 넘겨도 승격은 사람이 결정** |
| ⑤ 지식 박제 | 담당자 | `ops/articles/*.md` → `build_archive.py`, 관계도는 `erd-graph/` | 아카이브 아티클 · 온톨로지 노드/관계 |
| ⑥ 업무 카드 갱신 | 담당자 | 업무 보드 `task-board.html` (+ `board-saver.py`) | 카드 상태 · 다음 할 일 · AI 참조 로그 |
| ⑦ 종결 | 요청자 또는 담당자 | 창구의 [케이스 닫기] / 데스크의 「완료로 닫기」 | 상태 「완료」, 요청자 만족도(`req_score`) |

요청자의 만족도 · 담당자의 판정은 다음 봇 호출의 프롬프트에 「선례 판정 · 교정 노트」로 되돌아갑니다(자기 개선 고리).

## 2. 안전 불변식 (바꾸지 말 것)

1. **쓰기 서버는 localhost 전용.** 문의 데스크(5177)와 보드 저장 서버(5178)는 `127.0.0.1` 에만 묶고 Host · Origin · `X-Requested-With` · `Sec-Fetch-Site` 를 검사합니다. 보드 저장은 추가로 쓰기 토큰(`_saver_token.js`, 커밋 금지)을 요구합니다.
2. **공개 쓰기 엔드포인트는 셋뿐.** 접수 창구가 받는 쓰기는 `/api/new` · `/api/followup` · `/api/close` 세 가지입니다. 스크린샷은 이 둘(새 문의 · 추가 질문)에 **실려서만** 들어옵니다. 수정 · 상태 변경 · 삭제 엔드포인트를 만들지 않습니다. (로그인 · 프로파일 · PIN 은 계정 관리 경로입니다.)
3. **AI 표기는 의무.** 봇 답의 첫 줄 표기(`[트리니티봇 · AI 1차 안내 · 담당자 부재중]`)는 쓰기 게이트가 강제로 붙이며, 이어 붙인 답에서도 지우지 않습니다. 이름을 붙여도 AI 라는 사실은 숨기지 않습니다.
4. **아카이브 앵커는 내부 정보.** `ref`(`#아티클id`)와 내부 메모(`[[내부]]…[[/내부]]`)는 요청자 화면에서 지워집니다(`intake-server.py` `_public_view`). 요청자 화면의 「비슷한 답」도 본인 문의끼리만 비교합니다.
5. **봇에게는 쓰기 권한이 없다.** 봇은 셸 · 파일 쓰기 · 하위 에이전트가 막힌 읽기 전용 호출로 JSON 판정만 돌려줍니다. 기록 · 상태 변경은 쓰기 게이트가 `log-inquiry.py` 로만 하고, 재조회로 반영을 확인합니다. 게이트는 카드 번호 · 문의 번호 · 요청자 이름 같은 내부 식별자가 공개 답에 섞이면 막습니다.
6. **문의 로그는 append-only.** `inquiry-log.js` 는 `log-inquiry.py` 만 씁니다(같은 id 로 다시 push 하면 필드 병합 = 상태 전이 기록).
7. **봇 권한 확대는 장부가 근거, 결정은 사람.** 단계 기준은 `vacation/config.json` `stages` 에 있습니다.

## 3. 봇을 켜고 끄기

- 기본은 꺼짐. `python ops/task-dashboard/vacation/mode.py on | off | status | report`.
- Claude Code CLI(`claude`)가 필요합니다. 호출은 격리(개인 설정 · 훅 미적재, 쓰기 · 셸 차단, 웹 조사는 호출당 검색 3 · 페이지 2)됩니다.
- 회사별 규칙은 `ops/task-dashboard/bot-operating-rules.md` 에 채웁니다. 감시자는 이 파일의 §0 · §2 · §3~§6 을 프롬프트에 붙입니다.

## 4. 공개판에서 빠진 것

- 실데이터(문의 · 프로파일 · 카드 · 아티클 · ERD 추출본 · 봇 장부/행동 기록), 회사 고유 SAP 오브젝트 이름(→ `ZXX_*` 자리표시자), 사내 그룹웨어 · ITSM 연동 내용.
- 봇 단위 시험 묶음(실운영 기록에 의존) — 접수 · 데스크 회귀 시험(`chat-ui/tests/reproduce_defects.py`)과 스모크 시험만 포함.
