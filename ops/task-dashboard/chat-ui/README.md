## 화면 구조 — 카톡형 대화방 (2026-11-17 개편 · DEV-066)

**문의 1건 = 대화방 1개.** 예전처럼 모든 문의를 한 줄로 길게 늘어놓지 않는다. 화면만 바뀌었고 **서버 쓰기는 그대로 세 가지**(`/api/new` · `/api/followup` · `/api/close`)다 — `chat-server.py`·`intake-server.py`는 이 개편으로 바뀌지 않았다.

| 화면 | 주소 | 하는 일 |
|---|---|---|
| 대화 목록 | `/`(뒤 `#` 없음) | 내 문의를 최근 활동 순으로. 줄마다 마지막 말한 사람(원/담/나) · 제목(첫 질문 첫 60자) · 상태 칩 · 마지막 메시지 · 시각, 안 읽은 답에 「새」 배지. 거르기: 전체 / 새 답 / 진행 중 / 종결 |
| 대화방 | `#r/<문의번호>` | 그 문의 한 건만. 쓰는 칸은 **늘 그 문의에 이어 쓰기**(트리니티봇 처리 중이면 「지금 보내기」). 추가 질문을 더 못 받는 문의(`can_ask=false`)는 쓰는 칸을 숨긴다. 「케이스 닫기 및 평가」는 예전 그대로 |
| 새 문의 | `#new` | 유형 고르기 + 글 · 사진. 쓰는 동안 **내가 전에 받은 답 중 비슷한 것**을 최대 3건 보여 준다(누르면 그 대화방). 보내면 새 대화방으로 넘어간다 |
| PC(1000px 이상) | — | 메신저형 두 칸: 왼쪽 목록이 늘 보이고 오른쪽이 대화방 / 새 문의(목록 화면 대신 새 문의가 기본) |

- **휴대폰 「뒤로」** = 주소의 `#` 기록이라 대화방 → 목록으로 돌아온다.
- **접속자 카드**(2026-11-18 담당자 제안): 대화 목록 아래 고정 — 성함 · 소속 · 담당 업무 · 사번 · 「미완료 문의 N건」(누르면 진행 중만) · 「새 답 N건」 · [내 정보] · [로그아웃]. 휴대폰은 목록 화면에만, PC 는 왼쪽 목록에 늘.
- **사번 형식 경고**: 처음 오는 사번이 보통 형식(숫자 8자리, `EMP_FMT`)과 다르면 가입 화면에 「오타가 아닌지 확인」 경고만 띄운다(막지 않는다 — 예외 사번 · 시험 계정 허용).
- **안 읽음**: 브라우저 `localStorage` `sd-intake-me-v1.read`(사번별 `{문의번호: 답 지문 rev}`)에 「마지막으로 본 답」을 적는다. 처음 들어온 기기는 지금 있는 답을 읽은 것으로 시작(옛 답에 배지가 쏟아지지 않게). **기기마다 따로**다 — 다른 PC 에서 본 것은 이어지지 않는다.
- **쓰던 글**: 대화방 · 새 문의마다 따로 기억한다(그 화면 메모리 안에서만 — 새로 고침하면 사라진다).
- **비슷한 답 찾기**는 화면 안에서 내 문의(`/api/mine`)끼리만 비교한다(한글 두 글자 · 영숫자 낱말 겹침, 점수 0.35 이상). ⛔ **아카이브 문서 · 남의 문의는 보이지 않는다** — `intake-server.py` `_public_view` 설계 원칙 5(아카이브 앵커 = 내부 정보)를 지킨다.
- 시험: 2026-11-17 시험 서버 5183 에서 목록 · 대화방 이어 쓰기 실제 전송 · 새 문의 실제 전송 → 대화방 이동 · 비슷한 답 제안 · 안 읽음 배지 · 쓰던 글 보존 · 휴대폰 뒤로 · 케이스 닫기 · 휴대폰/PC · 밝게/어둡게(대비 4.5:1 미달 0) 확인, `tests/reproduce_defects.py` 8/8 PASS.

## 로그인 · 저장 — 무엇이 어디에 남나

| 무엇 | 어디 | 서버를 껐다 켜면 |
|---|---|---|
| 문의 · 답 · 추가 질문 · 종결 · 평가 | `inquiry-log.js`(기존 그대로 — 대시보드 · 트리니티봇 · 장부가 읽는 정본) | 그대로 |
| 사람(사번 · 성함 · 소속 · 담당 업무 · 예전 소속 · 이 서버로 남긴 문의 번호) | 운영 `…\SAP SD\_intake-profiles\profiles.json` / 시험 `…\_intake-profiles-chat-test\` — **공유 아카이브 밖**(첨부 폴더와 같은 줄) | 그대로 |
| 로그인 세션 토큰 | 서버 메모리에만(디스크에 쓰지 않는다) | 사라짐 → 화면이 기억한 사번으로 **조용히 다시 로그인** |
| 첨부 사진 | 기존 규칙 그대로(문의가 종결되면 자동 삭제) | 그대로 |

- 처음: 사번 → 「처음 오셨습니다」 → 성함 · 소속 · 담당 업무 등록. 다음부터: 사번만. 브라우저가 사번을 기억해 열면 바로 들어온다.
- 기록의 요청자 칸(`req`)은 지금처럼 「성함·소속」이다 → **대시보드 · 트리니티봇 · 장부 · 복귀 보고서는 바뀌는 것이 없다.**
- 한 사람의 문의 = 그 사번이 쓴 적 있는 (성함, 소속)으로 남긴 웹 접수 ∪ 이 서버로 남긴 문의 번호.
  → 예전 화면에서 같은 성함·소속으로 남긴 문의도 이어서 보이고, 소속을 바꿔도 예전 문의가 계속 보인다.
- 화면이 보낸 성함 · 소속은 믿지 않는다 — 서버가 프로파일로 채운다. 남의 문의에 추가 질문 · 닫기 · 사진 보기는 막힌다.
- 접수번호만으로 남의 문의를 보는 `/api/my`(운영 서버에는 열려 있음 · 화면은 안 씀)는 이 서버에서 열지 않는다.

## 알려진 한계 (보안 — 담당자가 알고 정할 것)

- **선택 PIN**: 기본은 사번만으로 로그인하되, 원하는 사용자는 가입·내 정보에서 4~8자리 숫자 PIN 을 설정할 수 있습니다(`PBKDF2-HMAC-SHA256` 무작위 솔트 해시, 5회 실패 시 5분 잠금, 잊은 경우 담당자가 `accounts.py clear-pin <사번>` 으로 해제).
- 로그인 화면이 「등록된 사번인가」를 알려 준다(등록 화면을 띄우려면 필요) — 분당 20회 제한과 Host 허용목록(`ALLOWED_HOSTS`)·CSRF(`Origin`/`X-Requested-With`/`Sec-Fetch-Site`) 방어가 적용됩니다.
- `/api/shot` 은 URL 쿼리 토큰 없이 `HttpOnly; SameSite=Strict` 세션 쿠키로 인증합니다.
- 공용 PC 보호: 사번이 브라우저에 남는다 → 내 정보 › 로그아웃(`/api/logout` 으로 서버 세션·쿠키 즉시 파기), 또는 작성 중인 글이 비어 있을 때 30분 유휴 시 자동 로그아웃.
