# desk — 담당자 통합 화면 (복귀 보고 · 검토 · 현황)

> 복귀한 담당자가 「무엇부터 볼까」를 한 화면에서 정하고, 트리니티봇 답 판정과 답변까지 그 자리에서 한다.
> **이 PC 전용 `http://127.0.0.1:5177/`** — 제어판 「바로 열기 › 🧭 복귀·검토·현황」이 서버를 띄우고 연다.
> 작성 2026-11-13 · DEV 카드 미등록(담당자 결정 대기) · 제어판 백업 `dashboard-panel.pyw.bak_20261113_desk`.

## 화면 구성 (2026-11-17 — 메일함형 · Ops Console 허브)

- **위쪽 메뉴**: `templates/ops-console.md` 정본 그대로(문의 데스크 · 대시보드 · 아카이브 · ERD · 봇 지표 · 협업 지표). 색은 같은 문서의 `--oc-*` 토큰 — 기기 설정에 따라 어두운 화면.
- **왼쪽 목록**: 검토할 트리니티봇 답 + 답을 기다리는 건을 한 목록으로(긴급문의 먼저). 거르기 전체 · 검토 · 답 대기.
- **오른쪽 상세**: 고른 건의 판정 칸(맞음 · 보완 · 틀림 + 이유 + 메모 + 답) 또는 답 칸. 기록하면 다음 건이 자동으로 골라진다.
- **키보드**: `j`/`↓` 다음 · `k`/`↑` 이전 · `Enter` 판정·답 칸으로(입력칸 안에서는 동작하지 않음). 900px 이하에서는 목록 → 상세 → 「← 목록으로」.
- **현황**(접을 수 있음): 숫자 타일 · 신뢰도 · 지식 공백 · 창구 끊김 · 다시 볼 답 — 목록 아래.

## 쓰는 것은 둘뿐 — 둘 다 `log-inquiry.py` 로만

1. **트리니티봇 답 판정** — 맞음 · 보완 · 틀림 + 이유 코드(`vacation/config.json` `reason_codes`) + 메모. `--grade` · `--grade-code` · `--grade-note`.
2. **담당자 답변** — 답 칸에 `──── 추가 답변 (시각) ────` 으로 이어 붙인다(표기 없는 블록 = 사람의 답). 「완료로 닫기」를 고르면 `--done`,
   아니면 상태를 「대기」로 둔다.

쓴 뒤에는 로그를 다시 읽어 반영을 확인한다. 대시보드(`task-board.html`)의 「✏️수정 › 🤖 트리니티봇 답 판정」과 같은 필드에 쓰므로 어느 쪽에서 해도 된다.

## 지킬 것

- **127.0.0.1 에만 묶는다.** 전원 문의 · 내부 메모가 다 보이고 쓰기 API 다 — 사내망에 열지 않는다(`board-saver.py` 와 같은 규칙).
- 접수 서버 · 저장 서버와 합치지 않는다. 휴가모드를 켜고 끄지 않는다. 트리니티봇을 부르지 않는다.
- 판정 기준 · 단계 계산을 여기에 새로 만들지 않는다 — 장부가 정본이다.

## 알려진 한계

- 지식 공백 묶음은 어미·불용어 제거 후 T-Code(예: `VA01`) + 2-gram 유사도로 묶어 정확도를 높였으나, 여전히 임베딩 기반 의미 검색과 달리 표현이 완전히 다르면 분리될 수 있습니다.
- `read_log()` 는 한 줄·여러 줄 JSON `push` 를 모두 파싱하며 `(st_mtime_ns, st_size)` 캐시로 반복 새로고침 비용을 줄입니다. `heartbeat()` 는 바이너리 오프셋·스레드 락으로 CRLF 오차 없이 증분 읽기합니다.
- 로그인 없음 — `127.0.0.1` 전용 + `Host`/`Origin`/`X-Requested-With`/`Sec-Fetch-Site` 검증 및 UI CSP 적용.
- `desk.html` `paint()` 는 새로고침 시 작성 중인 입력칸 포커스·커서·열린 `<details>`·스크롤 위치를 유지합니다.
